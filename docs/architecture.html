Architecture decision · 26 Aug 2026

The vault sees a file. The vault never owns it.

A renderer-neutral external-file bridge, forked from Folder Bridge. It gives Obsidian a temporary TFile; VSCode Editor supplies local Monaco, and core Web Viewer owns rendered HTML.

What lives where

Persistent address

The plugin stores a small per-device map: pyblocks → /home/bam/pyblocks. Links use the stable ID.

Ephemeral vault presence

Opened paths exist as in-memory TFolder/TFile objects for the session, then disappear on unload.

Untouched source bytes

The real file remains outside the vault. No copy, symlink, placeholder, or Sync payload is created.

Portable link contract

obsidian://external-file?mount=pyblocks&path=src%2Fexample.py&line=42&view=source
  • mount: stable machine-local mapping
  • path: contained relative path
  • line: optional navigation hint
  • view: source or rendered intent

Hard ownership boundaries

External File Bridge
  • Protocol + mount registry
  • Security + virtual adapter
  • Session injection + rehydration
  • Watcher reconciliation
VSCode Editor
  • Bundled Monaco runtime
  • Language modes and editor UI
  • Code/text extension ownership
  • Separate install and updates
Obsidian core + CLI
  • Core Web Viewer for rendered HTML
  • Normal media/PDF views
  • link-for emits links
  • link-doctor validates links
